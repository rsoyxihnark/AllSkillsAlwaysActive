WHAT THIS MOD DOES DIFFERENTLY? - ALL 10 EXISTING MODS EXAMINED

Important: since they all edit the same files; other similar mods are incompatible with mine. Only one of them should exist. (They are not required anymore anyways)


416 - Active Learner - J_Slash: Applies every skill on learn by rewriting the learn/block/reset functions. No exceptions, so alternate sign modes get forced on, and its base predates even the B&W mutation system (~1,300 lines behind today's file), so it cannot compile on next-gen. Ours: current verified base, and seven behavior-replacing skills stay slot-based so normal casts survive.
496 - Slots Slots SLOTS - Zur13: Works today and is maintained - we verified its base is current (only 14 vanilla lines changed). Different philosophy: he fixes the slot shortage with ~100 extra slots, config menus and a modified GUI across several files; we make slots unnecessary with one file and zero config.
546 - AllSkillsActive - Elys: The most elegant trick here: invisibly creates hidden slots and auto-sockets every learned skill, so vanilla logic just works. But its early next-gen base no longer compiles today, the hidden slots are written permanently into your save, and with no exceptions the alternate signs replace your normal casts.
765 - modPerksOnline - deltaone: The 2015 ancestor - he discovered the activeSkills mechanism every descendant (ours included) still uses. Perks-only, blocks socketing listed perks, pre-expansion base that cannot compile on any modern patch. Ours is the same idea four generations later: current base, 73 skills, socketing allowed for mutagen synergy, corrected accounting.
920 - Perks Always Active - wlsdks0706: deltaone's framework ported to day-one next-gen, perks only. That base lacks functions later patches added, so it fails against current files - and even when it worked, it activated a quarter of what ours does.
5539 - Skills Always Active - Aephiex: Source of the smartest decision in the lineage: the first to keep the five alternate sign modes, Gorged on Power and Battle Frenzy slot-based, because they REPLACE behavior. But his base is ~250 lines behind today's file and no longer compiles, and his install required the Potion of Clearance ritual - ours activates existing skills automatically.
7156 - Perks Always Active - JustAnOrdinaryGuy: Compiles today (we proved its base is byte-identical to current vanilla) and its accounting is correct. But it covers only the 20 General perks, and its own page requires a Clearance respec on existing saves. Ours: 73 skills, no potion, no ritual. It works - it does a fifth of the job and asks more at the door.
7256 - (All) Perks Always Active - JustAnOrdinaryGuy: Our closest ancestor, inherited with gratitude: current base, correct condition, full list. Two gaps are why ours exists: it force-activates the five alternate sign modes (Igni permanently firestreams), and on an existing save it stays inert until the mandated Clearance respec. Ours is this minus the Seven, plus automatic mid-playthrough activation, no Potion of Clearance, close and launch game, redistribute ability points, etc. NOT NEEDED.
7223 - Let all skills work - ItsukiKinomoto: The copy we examined ships the framework with an EMPTY activation list - it compiles and changes nothing until you edit the file yourself. It also carries the original 2015 condition: harmless for perks, but it double-stacks the path bonuses once you add tree skills, which is exactly what its premise invites. Ours ships the full list pre-built, with the corrected, math-traced condition.
8355 - (Overleveled) Skill always active - dnbnhlp: A different product: buy a skill to double max level, paying double points, and it becomes permanent. Compiles and works - as a purchase system, across two files. Ours activates free on learn, in one file. His is not broken; ours gives at level 20 what his sells at level 40.


THE MUTATION MODS - 3 MORE EXAMINED, SEPTEMBER 2026

Since this mod now makes mutations active too, the three that already did are worth the same treatment. All three share one implementation of the same idea, and it is a different idea from ours: they turn the equipped mutation into a list and give you a panel to pick several, so you choose which run. Ours has no panel and nothing to configure: research it and it is on. If you want Euphoria alone, theirs does something ours will not.

11960 - All Mutations Always Active - sortX: The origin of the design the other two share. It turns the equipped mutation into a list, adds the panel, and corrects vanilla's combat-start chain so each active mutation still fires rather than only the first. But the copy we examined ships a signEntity.ws taken from classic 1.32 inside a next-gen mod (99.8% match to 1.32, 91% to 4.04), so installing it takes away the Igni firestream throw and alternate sign casting, and its info.json still carries unfilled placeholder text. Ours: mutations with no panel, two files, and a base proved line by line against a real 4.04 install.
12795 - ModActiveAllMutations - gamerfriki111: The same implementation as 11960, and the cleanest packaged of the three: three files, the game's own UTF-16 kept throughout, no dead files, no placeholder text. Same multi-equip philosophy, so the panel is still where you choose. Ours activates every mutation you have researched, with nothing to pick.
12843 - All Mutations and Skills and Enchanting - Alexz_915: 11960's mutation code, identical apart from the author tag, with a skills list and a runeword change added on top. Its skill list is ours plus the Seven, so Igni permanently firestreams, and it carries no on-load catch-up, so an existing save stays inert until a Potion of Clearance. It also ships a signEntity.ws byte-identical to vanilla, which changes nothing and only adds one more file for Script Merger to argue about. Ours: the Seven stay slot-based, and an existing save activates on first load.

One bug found by reading all three, and fixed here: vanilla checks mutations at the start of a fight with a single if/else chain, which is safe only while one mutation can be active. Make several active and the chain stops at the first, so the rest quietly do nothing. All three of these mods had to correct it, and so did we.
